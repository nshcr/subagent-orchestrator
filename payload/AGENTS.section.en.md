## Subagents and parallelism

- Default to a single agent. Use `$subagent-orchestrator` only when the user explicitly requests delegation or parallel work, or when a host/owner-qualified bounded child can replace material primary work or provide a required independent gate; complexity, file count, decomposability, or idle capacity alone do not qualify.
- Once delegated, follow the skill's current routing and evidence-bus slice, topology, task-wide ownership and ledgers, immutable handoff, trace-external host authority receipts, waiting, freeze, message, and gate rules; one unique task occupies one trace scenario and rollover cannot reset task-wide state. Slice owner paths bind every writer path/component and path artifact. Every work transfer has the complete exact-key canonical schema and binds spawn depth. Materiality authority binds an external issuer class and rejects primary or any pre-indexed child, parent, role, or agent identity as issuer. Trace hashes bind payloads but do not authenticate issuers; message authority binds exact purpose plus canonical dependency and semantic-message digests, and a bounded-peer artifact relay must come from the named producer's terminal receipt. High-risk final states require fresh, independent, read-only, disjoint gates on one filesystem hash. The primary always retains authorization, scope, conflict handling, integration, and final acceptance; children cannot expand authority, governed roles remain leaves, only a capability-and-relay-qualified bounded peer may delegate one level, and every required descendant must reach a terminal state before the primary ends.
