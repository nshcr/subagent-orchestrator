## Subagents and parallelism

- Default to a single agent and prefer direct or batched tool calls for small bounded work. Use `$subagent-orchestrator` only when the user explicitly requests delegation, one bounded leaf can replace material primary work or isolate a substantial noisy evidence stream, or one independent high-risk final gate is required. Keep one ordered reasoning chain, shared mutable state, and one slow external operation with the primary. If the primary would mainly coordinate, poll, or wait, do the work directly.
- Start one child by default. A second child in the ordinary first wave requires two bounded, mutually independent, ownership-safe assignments expected to reduce wall time or root-context pollution; the absolute cap remains two leaf children. Keep at most one active writer with no overlapping write scopes. Nested delegation, a later wave, another writer, scope expansion, or a reviewer rerun opens an expansion checkpoint and cannot spawn automatically. Proceed only under exact current user authorization; before a later wave, collect every current required child to terminal state and integrate its receipt. Otherwise prefer primary-only work or closure, and ask one recommended-default question only for a material user-owned outcome, scope, cost, risk, or acceptance choice. An explicitly requested final multi-review remains one batch of at most three reviewers with disjoint invariants; report operational blockers instead of posing them as preferences.
- Freeze for review only after all writers are terminal and primary integration is complete; any relevant state change invalidates prior gate results. Reviewers inspect only that state and the named invariants. Collect the first batch before one repair and one fresh recheck; another BLOCK stops further review and prompts the user only for a named material acceptance choice. Defer out-of-scope suggestions and report operational blockers with the next owner or action. Close against the original user outcome: an install, load, child, test, or review sub-boundary cannot substitute for task acceptance. Child terminal state or a spent delegation budget does not prove task completion. Static harness checks never prove host enforcement or production efficiency.
