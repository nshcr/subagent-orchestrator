# 子代理编排

优化已完成的用户结果，而不是代理活动。先验证核心行为，再建设支撑设施：识别与用户最相关的最难行为，取得其最小真实证明，在此之前推迟辅助机制。

## 锚定与路由

1. 从主代理单独开始。记录请求结果、已确认约束、最短直接证明，以及子代理将替代的实质工作。把这些内容作为验收锚点；安装、子代理、测试或审查都不能替代它。
2. 小型工作优先直接调用或批量调用工具。仅委派能够替代主代理实质工作、用简短收据隔离嘈杂证据，或提供必需独立门禁的有界叶子任务。复杂度、文件数量、剩余容量和寻求信心都不足以构成委派理由。
3. 首个普通叶子使用宿主角色说明；无法匹配的工作留在主代理。自定义角色、第二个子代理或审查前，先阅读 [路由策略](references/routing-policy.md)。命名一个非 `default` 的 `agent_type`；操作叶子使用 `fork_turns: "1"`，新鲜审查使用 `"none"`。不得省略类型，也不得使用更大或完整历史分叉。使用精简的 [委派契约](references/delegation-contracts.md)，要求英文的模型面向收据，并由主代理综合面向用户的结果。
4. 主代理必须继续承担实质工作。保留授权、范围、单一写入者整合、发现裁决和最终验收。如果主代理主要只是在协调、轮询或等待，就减少委派并直接完成工作。

## 约束拓扑与扩展

- 允许委派时先启动一个子代理。只有在任务有界、相互独立、所有权安全，并预期减少耗时或根上下文污染时，才增加普通首波的第二个子代理。普通上限为两个子代理和一个活动写入者；写入范围不得重叠。
- 每个子代理都必须是叶子。不得允许子代理继续委派或与同级通信。扩展检查点不得放宽递归、所有权、写入范围或状态新鲜度规则。
- 后续波次、增加写入者、扩大范围或重新运行审查都构成扩展检查点。冻结新的生成，收集并整合当前必需的收据，然后重新锚定原始结果。
- 只有当新证据为下一个子代理提供一个有界且不重叠的目的、实质结果与风险保持不变，且委派成本低于直接完成时，才可无需询问清除检查点。一次最多清除一个新子代理；明确要求的多重审查批次是唯一例外。
- 当用户要求检查点，或证据留下关于结果、验收、外部行为、兼容性、安全、隐私、架构、重要成本、迁移或不可逆影响的实质性用户决策时，应在实施前询问。说明证据，推荐一个默认选项及其权衡，并提出一个要求用户选择行动的问题。用户纠正和刹车反馈会使相冲突的计划惯性失效。
- 对能力或访问阻塞，报告下一位负责人或下一步动作；不要把它伪装成偏好。操作叶子在无法获得批准时，其终态收据必须写明权限类别、动作和所有者范围，形成任务范围内的权限回路。在宿主证明存在适用于子代理的共享授权前，不得在该边界上重试、恢复或启动后续子代理；主代理直接完成剩余工作。
- 对操作叶子（`explorer`、`worker`、`evidence_tester`、`boundary_mapper`），主代理通过 `send_message` 和 `followup_task` 合计最多更新一次。仅发送原范围内新准入的证据、缺失的验收字段或新的失败证据。不得更新审查角色；审查证据变化必须重新冻结并启动新审查。不得轮询。若两次面向决策的尝试仍未改变同一不确定性，就停止角色变体，在主代理中取得最小区分性观察。

## 审查与收敛

1. 仅在存在明确命名的高风险不变量或用户明确要求时准入独立审查。把对抗性审查视为用具体证据证伪该不变量，而不是独立角色、重设计邀请或默认收尾仪式。明确要求的多重审查限为一次批次，最多三个新审查者，针对同一冻结状态中的互不重叠不变量。
2. 只有所有写入者终止、主代理完成整合和直接检查后才冻结。任何相关变更都会使此前的门禁结果失效。审查者是证据门禁，不是设计者或需求来源。
3. 主代理必须依据验收锚点和证据裁决每项发现：接受已证明的阻塞，说明理由后拒绝无证据或超范围的主张，延后非阻塞改进。不得仅因审查者提出建议就实施。
4. 修复已接受的阻塞，直接验证，重新冻结并执行一次新复核。如果仍然阻塞，停止自动审查循环并回到第一性原理。判断是哪个不变量失败、发现已过时/无效，还是哪一项最小证据或修复会改变决策。
5. 适当时继续由主代理进行有界直接修复，无需再次审查。如果同一主张仍需独立证明，将下一次新审查视为新的扩展检查点。必须有变更后的候选状态或新的区分性证据；未改变的 BLOCK 是证据平台期，不是继续审查驱动迭代的许可。
6. 只有在一次有效的 `risk_reviewer` 返回有证据依据的不确定结果，且该结果可能改变不可逆的 P0/P1、安全、授权或数据完整性决策时，才使用 `risk_reviewer_max`。不得把它当作常规第二意见。

## 以证据收尾

- 不重放扫描，抽样检查子代理证据和其所有 artifact。验证 `agent_type` 为非 `default`，操作叶子的 `fork_turns: "1"`，审查角色的 `"none"`。拒绝省略、更大、已解析的 `default` 或完整历史结果；不要重新生成子代理。使用已安装的子代理模型和推理设置，不按任务重新调参。
- 在安全且获授权的主代理工作仍可能按比例降低任务相关风险时继续推进。只有针对原始结果取得与主张匹配的证据、明确放弃/被替代，或出现真实的用户级阻塞时才收尾。
- 静态策略测试只能作为本地一致性证据。安装和客户端回读只能证明已加载，不能证明生产效率。源代码层证据标记为 `verified-local`。
- 在最小真实任务证明核心收益前，不要新增 harness、schema、安装器功能、授权系统、审查层级或 benchmark。当编排开销接近其替代的工作量时，停止委派。

仅在发生路由变更或提出效率主张时，阅读[评估策略](references/evaluation-policy.md)。
