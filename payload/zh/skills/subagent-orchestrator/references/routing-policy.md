# 高级路由策略

本 reference 只补充 Skill，不扩大其准入、授权、所有权或叶子边界。仅在增加第二个子代理、进入后续波次、发生自定义角色转换或开展审查时读取。

## 选择与转换

| 需求 | 路由 | 必需的转换条件 |
| --- | --- | --- |
| 能替代实质探索的狭窄只读代码库问题 | 内置 `explorer` | 将证据返回主代理；只有主代理能确定策略 |
| 策略已确定的实现切片 | 内置 `worker` | 已明确准确的所有权和验收条件；审查前由主代理抽样并整合 |
| 嘈杂的结构化测试或有界日志 | `evidence_tester` | 仅当一个 artifact 能够有效隔离主代理上下文中的原始证据时使用 |
| 未解决的执行、状态或持久化边界 | `boundary_mapper` | 主代理的定向检查不足；返回证据，不作设计结论 |
| 明确的高风险不变量 | 新启动的 `risk_reviewer` | 写入者已终止，且整合后的候选状态已冻结 |
| 有证据支持的不可逆歧义 | `risk_reviewer_max` | 有效的审查升级已提供委派契约要求的全部字段 |

不得替换角色，也不得把无法匹配的工作路由给内置 `default`。审查返回的 BLOCK 交由主代理裁决，且不会自动授权 `worker`。PASS、BLOCK、证据缺失或普通不确定性都不得路由到 `risk_reviewer_max`。

## 扩展与审查

- 普通首轮的第二个子代理必须任务有界、相互独立、所有权安全，并预期减少耗时或降低根上下文噪声。保持两个子代理、一个活动写入者的普通上限，且写入范围不得重叠。
- 进入后续波次、增加写入者、扩大范围或重新运行审查前，先收集并整合当前必需的收据。新证据必须给出一个有界的后续目的，同时实质结果和风险保持不变。扩展本身不是需要询问用户的问题。
- 多重审查需用户明确要求：一个批次、最多三个新审查者、互不重叠的不变量和一个冻结候选状态；不得投票或举办设计工作坊。
- 一次修复和新复核后仍为 BLOCK 时，交回主代理按第一性原理裁决。再次审查必须有变更后的候选状态或新的区分性证据。两次尝试仍未改变同一不确定性时，将其视为证据平台期，直接取得最小区分性观察。

## 运行边界

操作叶子和新审查使用各自声明的角色边界与隔离执行上下文。使用英文收据和已安装的设置：内置角色为 Terra/max，`evidence_tester` 为 Luna/max，`boundary_mapper` 为 Terra/max，`risk_reviewer` 为 Sol/xhigh，`risk_reviewer_max` 为 Sol/max。主代理的模型与推理设置仍由用户控制。

将 `sandbox_mode` 视为请求的配置，而非硬授权边界；父级覆盖可能改变实际访问权限。无论宿主授予何种权限，都必须保留各角色更严格的动作和写入边界。
