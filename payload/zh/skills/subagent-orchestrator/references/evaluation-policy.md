# 评估策略

## 仅用于比较

本 reference 仅用于实际的路由比较或效率主张。它不约束 Skill 的日常执行，不改变委派准入条件，也不要求普通任务在执行前开展 benchmark。

评估用户要求的结果：最终交付物、验收条件、重要约束，以及与主张匹配的证据。代理数量、活动量、策略复杂度、安装结果或门禁结论都不能替代该结果。

## 最小比较

- 在能够回答路由问题的最小代表性成对任务上，比较仅由主代理执行与采用委派的路径。
- 开展角色或模型 A/B 时，固定任务、交接、候选、验收和证据面，仅改变已配置路由；通过宿主回读确认实际模型和推理强度。没有代表性成对结果，不得提出模型因果主张。
- 首先保留授权和正确性。只有质量不下降且端到端开销显著降低时，才考虑改变路由。
- 如果委派既未替代实质工作、减少根上下文噪声，也未提供必需的独立门禁，就停止比较。
- 只有确有比较决策时才使用仓库的 campaign evaluator。不要对常规 Skill 使用做 benchmark；未经明确授权，不要再构建测量框架。

## 记录的证据

- 最终结果与正确性失败；
- 子代理尝试、波次、写入者、审查尝试、重试和主代理重放；
- 分开记录原始审查者调用和有效评审；把每个终态调用分类为正常完成、缺字段拒绝、因候选变化或新证据而被替代的实质 BLOCK、授权阻塞、超时或失联；证据不足时按不可分类处理；
- 每个新增子代理或后续波次所替代的工作量，或所减少的根上下文噪声；
- 将重叠写入者、未整合收据、对变化中状态的审查、过宽交接，或在相同受阻权限边界上重复启动子代理记录为路由失败；
- 等待超时只作为遥测，不作为失败；
- 首轮门禁通过率、修复轮数、缺字段重试率、不重叠等待时长、空等待轮询次数和总收敛时间；
- 可用时记录主代理和子代理的总 token 或实际 credit，并将缓存的原始用量与计费 credit 分开；
- 按实际证据层级记录源代码、安装、客户端回读和目标状态观察。

不要从线程总量推断各角色或工具的 credit，也不要把 fixture 描述为生产证据。保留原始观察，并说明无法取得的证据。
